# btsnoop 抓包速查

## 打开嗅探

设置 → 关于手机 → 连点「版本号」7 次 → 返回开发者选项 → **启用蓝牙 HCI 嗅探日志**。
打开后重启蓝牙（关一次再开），日志才会开始记。

## 取日志

root 设备：

```bash
adb root
adb pull /data/misc/bluetooth/logs/btsnoop_hci.log
```

非 root：开发者选项 → 生成 bugreport，解压后在 `FS/data/misc/bluetooth/logs/` 里找。

## 在 Wireshark 里定位

1. 打开 `btsnoop_hci.log`；
2. 过滤 `btatt.opcode == 0x52`（Write Command, without response）；
3. 找到 value 长度 17、开头 `11 01 55` 的那些；
4. 右键某一条 → `Apply as Filter → Selected`，只看这一个 handle；
5. 对照你在 App 里做的动作（右拖、左拖、快拖、慢拖），把变化字节与角度/方向/速度对应起来。

## 一段典型日志（右转 90°，mode 3）

```
No.   Time      Source  Value
...
12    1.203     Host    Sent Write Command, Handle 0x0016
                        Value: 11 01 55 01 02 08 00 00 01 03 88 88 88 88 00 0d 0a
13    1.804     Host    Sent Write Command, Handle 0x0016
                        Value: 11 01 55 01 02 08 04 00 01 03 88 88 88 88 00 0d 0a
```

- 第 12 条：`00 00` → 角度 0，唤醒帧
- 第 13 条：`04 00` → `0x0400 = 1024` → `1024/4096*360 = 90°`，`01` = 右
- 两条间隔 ≈ 601 ms → 就是那个 600 ms

左转 90° 只有第 3 个变字节不同：`04 00 00 03`（`DIR=00`）。慢速档把 `03` 换成 `01` 或 `02`。

## 排错

| 现象 | 原因 |
|---|---|
| 只有一帧 `00 00`，没有后续 | 你只按了一下方向键，App 发的是"开始" |
| 帧里的角度始终是 0 | App 只发相对增量前的重置，实际动作在你松手时才发 |
| 完全抓不到 17 字节帧 | 嗅探没开或蓝牙没重启；或 App 走的是系统 API 但 HCI 层被过滤 |
| 有大量 `1b 01 55 ...` 等其它帧 | 那是相机/拍照相关指令（原厂全景方案共用一条通道），忽略 |

> 原厂 App 除转向外还会通过同一特征发拍照、切换模式等指令，字节不同，转发那些指令到别的型号云台可能有风险，本仓库只保证转向与心跳。
